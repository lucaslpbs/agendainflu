## Codebase Patterns
- Pre-existing typecheck errors exist (TS2589 in cron/update-followers, TS2339 in BookingDetailDialog) — these are not blockers for commits
- `.env.local` is already in `.gitignore`; use `.env.example` for documenting required env vars
- `src/lib/db.ts` creates a Supabase client with service_role key for server-side API routes
- Many files have pre-existing uncommitted changes in the working tree — only stage files you actually changed
- `next.config.mjs` uses ESM; image remote patterns must stay in sync with CSP img-src in headers()
- For RLS policies, use `DROP POLICY IF EXISTS` + `CREATE POLICY` since Postgres doesn't support `CREATE POLICY IF NOT EXISTS`
- `clients` table has a `user_id` column (added in migration 4) linking to `auth.users` for client self-access
- Zod schemas are centralized in `src/lib/schemas/` — import from `src/lib/schemas` barrel export
- Database enums are in Portuguese — always match exact values from `src/integrations/supabase/types.ts`
- Zod validation pattern in API routes: `safeParse(body)` → if `!success` return 400 with `error.errors.map(e => e.message).join(', ')`
- Rate limiting: use `rateLimit(req, { key, limit, windowMs })` from `@/lib/rate-limit` — returns `NextResponse | null`; place before try-catch for public endpoints, after auth for user-keyed endpoints
- For secret comparisons, use `crypto.timingSafeEqual` wrapped in a helper that handles length mismatch (see `cron/update-followers/route.ts`)
- CORS for API routes is configured in `next.config.mjs` headers() with source `/api/:path*` using `NEXT_PUBLIC_APP_URL`
- For atomic database operations, use Postgres functions via `db.rpc()` — add function types to `src/integrations/supabase/types.ts` under `Functions`
- When adding RPC functions, use `SECURITY DEFINER` to bypass RLS for service-level operations
